# 機能定義書

機能ごとに、画面の動き・入力チェック・処理の流れ・API・使うテーブル・エラー時の動き・受け入れ条件をまとめたもの。
[機能要件](../features.md) の分類ごとに1ファイルにしている。実装とテストは、このドキュメントを見ながら進める。

## 各ドキュメントの構成（テンプレート）

新しい機能を追加するときも、この構成で書く。

```markdown
# 機能定義書：〇〇

## 1. 概要
目的と、対象の機能ID・機能名の表。

## 2. 前提条件・権限
ログインが必要か、誰が操作できるか。

## 3. 画面
関係する画面ID と、画面上の動き（ボタンの表示条件、成功・失敗時の表示など）。

## 4. 入力項目とチェック
項目・必須・チェック内容・エラーメッセージの表。

## 5. 処理の流れ
Mermaid のシーケンス図（ブラウザ → React → Spring Boot → DB / S3）。

## 6. 業務ルール
この機能に固有のルール。

## 7. API
使う API の ID・メソッド・パスと、機能固有の注意点。

## 8. 使うテーブル
テーブルと、読む（R）・書く（C/U/D）の区別。

## 9. エラー・例外時の動き
状況・HTTP ステータス・画面の表示の表。

## 10. 受け入れ条件
「これができたら完成」のチェックリスト。テストケースのもとにする。
```

## 共通の約束ごと

- エラーレスポンスの形とステータスコードの使い分けは [API設計「共通ルール」](../api.md#共通ルール) に従う
- ログインが必要な API で 401 が返ったら、どの画面でもトークンを破棄して S-01 ログインへ移動する（各機能定義書では省略する）
- 通信エラー（サーバーに届かない・500）のときは、画面上部に「通信に失敗しました。時間をおいてもう一度お試しください」と表示する（各機能定義書では省略する）
