# モックアップ実装計画書：X風SNSアプリ

## Context

[機能要件](./features.md)・[画面仕様・画面遷移・ユースケース](./screens.md)・[機能定義書](./feature-specs/README.md) を定義済みの段階で、本実装（React + Spring Boot）に着手する前に画面と動きを目視で認識合わせしたく、バックエンド・ビルドツール・フレームワーク・外部ライブラリ一切なしの静的HTML/CSS/JSでブラウザ上に動くモックを作成した。データはメモリ上のみで保持し、リロードで初期データに戻る（DB永続化は対象外・本実装で対応）。

配置場所は `mockup/`（リポジトリ直下、`docs/`とは独立）。前回のタスク管理アプリ（`github-demo`）のモックと同じ構成にした。今回実装予定の機能（F-01〜F-71、画面 S-01〜S-10、UC-01〜UC-18）を一通り盛り込んでいる。

## 作成ファイル

- `mockup/index.html` — ページ骨格（モックの注記、共通ヘッダー、各画面を描画する`<main>`、投稿作成／編集モーダル、確認ダイアログ、画像の拡大表示、トースト）
- `mockup/style.css` — 見た目（X風の1カラムレイアウト、投稿カード、タブ、フォローボタン、モーダル、いいねのハートの色、スマートフォン幅の最低限の対応）
- `mockup/script.js` — 画面ロジック（メモリ上のデータモデル、初期データ、ハッシュによる画面切り替え、描画、各種操作）

## データモデル（script.js内、メモリのみ）

[データ構造・ER図](./database.md) のテーブルと同じ形にした。いいね数・コメント数・フォロー数・フォロワー数は列として持たず、表示のたびに数える（本実装と同じ考え方）。

```js
const db = {
  users:    [ { id, username, displayName, email, password, bio, iconUrl, createdAt } ],
  posts:    [ { id, userId, content, images: [ { url, sortOrder } ], createdAt, editedAt } ],
  comments: [ { id, postId, userId, content, createdAt } ],
  likes:    [ { postId, userId, createdAt } ],
  follows:  [ { followerId, followeeId, createdAt } ],
};
```

初期データとして、次のものを用意した。

- ユーザー6人（`yamada`・`sato`・`suzuki`・`tanaka`・`yama_dev`・`hanako_k`）。パスワードはすべて `password123`。ログイン画面にデモ用アカウントとして表示し、クリックで入力される
- 投稿32件（`yamada` のフォロー中タイムラインが20件を超え、「もっと見る」を確認できる数）。画像1〜4枚つきの投稿、編集済みの投稿を含む。画像は SVG をその場で作って data URL にしている（外部ファイル不要）
- `yamada` の投稿の1つに23件のコメント（「さらに表示」と、自分のコメントの削除を確認できる）
- いいね（0件の投稿を含む）・フォロー関係

## 画面の切り替え

URL のハッシュ（`#/...`）で画面を切り替える。ページを読み込み直さないため、画面を移動したり、ログアウトして別のユーザーでログインし直したりしてもデータは消えない（第三者としていいね・コメントする動きを確認できる）。

| URL | 画面 |
|---|---|
| `#/login`・`#/signup` | S-01 ログイン・S-02 新規登録（ログイン済みなら `#/` へ） |
| `#/`・`#/all` | S-03 タイムライン（フォロー中・全体） |
| `#/posts/:id` | S-06 投稿詳細（`?focus=comment` でコメント入力欄にフォーカス） |
| `#/users/:username` | S-07 プロフィール |
| `#/users/:username/following`・`/followers` | S-09 フォロー中・フォロワー一覧 |
| `#/settings/profile` | S-08 プロフィール編集 |
| `#/search?q=...` | S-10 ユーザー検索 |

未ログインでログインが必要な画面を開くと `#/login` に移動する。S-04 投稿作成・S-05 投稿編集はモーダルで表示する。

## 実装した機能（画面仕様・機能要件との対応）

| 分類 | モックでの実装 |
|---|---|
| 認証（F-01〜F-04） | 新規登録の入力チェック（ユーザー名の形式・大文字小文字を区別しない重複、メールの形式・重複・小文字化、パスワード8〜72文字・確認一致）、登録後はそのままログイン。ログイン失敗時は共通メッセージを出してパスワード欄を空にする。ログアウト |
| 投稿（F-10〜F-13） | 280文字カウンタ（絵文字も1文字、超過で赤字・ボタン無効）、画像4枚まで・jpg/png/gif・5MBまで（プレビュー、×で外す）、本文も画像もないと押せない、入力中に閉じると確認。`…` メニューは自分の投稿だけ。編集は本文のみで「編集済み」を表示。削除は確認ダイアログ、コメント・いいねも一緒に消す。画像クリックで拡大表示 |
| タイムライン（F-20〜F-23） | フォロー中／全体タブ（URL も切り替え）、新しい順に20件ずつ「もっと見る」、タブごとの0件メッセージ（フォロー中はユーザー検索へのリンクつき） |
| コメント（F-30〜F-32） | 古い順に20件ずつ「さらに表示」、1〜280文字、追加すると末尾に表示してコメント数を更新、自分のコメントだけ削除（確認ダイアログ） |
| いいね（F-40〜F-42） | 押すとすぐにハートと数が切り替わる（画面全体は描き直さない）、0件は数字を出さない |
| フォロー（F-50〜F-52） | プロフィール・フォロー一覧・検索結果のフォローボタン（フォロー中にマウスを乗せると「フォロー解除」）、自分には出さない、フォロワー数の更新、フォロー中タイムラインへの反映。フォロー中・フォロワー一覧はタブで切り替え |
| プロフィール（F-60・F-61） | 表示（フォロー数・フォロワー数・投稿一覧）、編集（表示名1〜50文字、自己紹介160文字のカウンタ、アイコンのプレビュー、変更がある状態でのキャンセルは確認）。URL のユーザー名は大文字小文字を区別しない。存在しないユーザーのメッセージ |
| ユーザー検索（F-70・F-71） | ヘッダーの検索ボックスから移動、入力が止まって0.3秒後に自動検索（Enter で即時）、先頭の `@` と空白を除去、大文字小文字を区別しない部分一致、完全一致→前方一致→その他の順、`_` `%` は普通の文字として扱う、空なら最近参加したユーザー、URL を履歴を増やさずに書き換え |
| ユーザーへのリンク | 投稿カードの投稿者・コメントした人・一覧の行のアイコンと名前は、クリックでプロフィールへ（投稿カード内でも投稿詳細へは移動しない） |
| 差別化 | インプレッション数・リツイートのボタンは置かない |
| UC-01〜UC-17 | すべてモック上で動作する |
| UC-18（再訪問時のログイン状態） | 対象外（JWT・サーバーがないため）。リロードするとデータが初期化され、ログイン画面に戻る。画面上部に注記を表示 |

### モックでは再現しないもの

| 項目 | 本実装での扱い |
|---|---|
| JWT によるログイン状態の保持 | [機能定義書：認証](./feature-specs/01_auth.md) |
| S3 への画像保存 | 画像は data URL としてメモリに持つだけ（[インフラ構成](./infrastructure.md)） |
| サーバー側の権限チェック・入力チェック | 画面側のチェックのみ（本実装ではサーバー側のチェックを正とする） |
| 通信中の表示・通信エラー | 投稿・保存ボタンだけ0.3秒の「投稿中…」を表示。通信エラーは発生しない |

## 見た目・スタイル方針

- X風の中央1カラム（幅640px）。白い投稿カード、青のアクセント色、いいねはピンクのハート
- [非機能要件](./non-functional-requirements.md) の互換性要件（Chrome最新版・PC優先）に合わせ、スマートフォン幅は崩れない程度の対応（ヘッダーの検索ボックスを2段目に回す）
- アイコン画像が未設定のユーザーは、表示名の1文字目を色つきの丸で表示する
- ユーザーが入力した文字列はすべてテキストとして DOM に入れ、`innerHTML` は使わない（XSS 対策の練習を兼ねる）

## 動作確認方法

- `mockup/index.html` をブラウザ（Chrome）で直接開く（`file://` パス）、または `mockup` ディレクトリで `python3 -m http.server 8000` を起動して `http://localhost:8000` を開く
- ログイン画面のデモ用アカウント（例：`yamada@example.com` / `password123`）をクリックしてログインする
- 確認項目：
  - 新規登録（入力チェック・重複）、ログイン失敗、ログアウト
  - フォロー中／全体タイムライン、「もっと見る」
  - 投稿（文字数・画像の枚数・形式・サイズ）、編集（「編集済み」）、削除
  - いいね・いいね取り消し
  - コメントの追加・削除、「さらに表示」
  - 投稿者名・コメントした人の名前からプロフィールへ移動してフォロー
  - フォロー中・フォロワー一覧
  - ユーザー検索（`@ユーザー名`・表示名・大文字小文字・並び順・0件・空）
  - プロフィール編集（表示名・自己紹介・アイコン）
  - ログアウトして別のユーザーでログインし、第三者としていいね・コメントした数が反映されていること
  - ページリロードでデータがリセットされる（想定通りの挙動）

## 動作確認結果

Playwright（インストール済みの Google Chrome）によるブラウザ自動操作で、UC-01〜UC-17 に沿った93項目を確認し、すべて成功した（コンソールエラー0件）。主な確認内容は次のとおり。

- 未ログイン時のリダイレクト、ログイン失敗のメッセージ、新規登録の入力チェック（大文字小文字を区別しない重複を含む）、登録後の自動ログイン、ログアウト後に「戻る」でログイン後の画面に戻れないこと
- フォロー中タイムラインが自分とフォロー中の人の投稿だけで20件＋「もっと見る」、全体タイムライン、インプレッション・リツイートの表示がないこと、`…` メニューが自分の投稿だけに出ること
- いいねの切り替えと数の増減、0件で数字を出さないこと
- 投稿の文字数（281文字・絵文字280文字）、画像の形式・5MB・4枚の制限、投稿がタイムラインの先頭に出ること、編集で「編集済み」、入力中に閉じるときの確認、削除
- コメントの20件表示と「さらに表示」、古い順、自分のコメントだけ削除できること、コメント数の増減
- コメントした人・投稿者の名前からプロフィールへ移動してフォロー（フォロワー数・フォロー中タイムラインへの反映）、フォロー一覧の件数
- ユーザー検索（前方一致の並び順、0.3秒待ってからの検索、`@`・大文字での完全一致、表示名での検索、`_` の扱い、0件、空のとき、結果からのフォロー・解除）
- プロフィール編集（入力チェック、アイコンのプレビュー、保存後に過去の投稿カードの表示名も変わること）、URL の大文字小文字、存在しないユーザー・投稿
- 主要9画面に `null` / `undefined` の文字が出ていないこと、スマートフォン幅（390px）で横スクロールが出ないこと
- `file://` で直接開いた場合も、ログイン・タイムライン・検索が動作すること

確認中に見つけて修正した不具合：

- 「もっと見る」が不要なときに画面に `null` と表示されていた（`append` に `null` を渡していたため）
- コメント一覧の行のクラス名 `comment` が 💬 ボタンのクラスと重なり、ボタンの下に線が出ていた（`comment-item` に変更）
- 検索欄にブラウザ標準の×と自前の×が二重に出ていた（`type="text"` に変更）
